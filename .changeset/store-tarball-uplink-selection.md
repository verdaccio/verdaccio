fix: tarballs with missing distfile records and wrong uplink selection

Two long-standing tarball bugs, ported from the 6.x fix:

- **Missing `_distfiles` records made tarballs permanently 404.** The
  bookkeeping record is only created when a version is first merged from an
  uplink; manifests cached without it (or revalidated with 304) answered
  "no such file available" forever. `lookupDistFile` now falls back to the
  version's own dist metadata: the conventional `<name>-<version>.tgz` fast
  path first, then a full scan (which also resolves GitHub Packages style
  bare-digest tarball urls).
- **The uplink for a tarball was the last configured match, not the one
  serving it.** Selection now prefers the uplink recorded on the distfile,
  then the uplink whose url actually serves the tarball (so credentials of
  an unrelated uplink are never sent to it), keeps the single-uplink CDN
  behavior, and only then falls back to an autogenerated credential-less
  proxy.
